# Section Blueprints

This document defines reusable, premium section patterns to prevent generic AI-looking card layouts.

## 1. Media Overlay Hero

Use for:
- beauty salons
- hair & makeup studios
- bridal / special occasion businesses
- spa businesses

Structure:
- full-width or near full-width media area
- headline over media or beside media
- glass/transparent text panel allowed
- strong primary CTA
- no card-inside-card composition
- no crude placeholder text
- if no usable media exists, use art-directed fallback

Mobile:
- headline and CTA must appear early
- media should still be visible in first scroll

## 2. Split Editorial Hero

Use for:
- premium clean layouts
- clinics
- high-trust service businesses

Structure:
- 50/50 or 60/40 split
- text + media
- no generic card wrapper
- strong typography hierarchy

## 3. Visual Service Strip

Use on Home page:
- 3–5 featured services
- large vertical or horizontal media cards
- overlay/glass captions
- clear link to Services page
- must not be plain equal white cards

## 4. Service Dossier Layout

Use on Services page for hair/makeup/salon:
- each service is a dossier block
- service number
- title
- short description
- media area
- WhatsApp CTA
- optional tabs for 2–3 media items
- thin dividers
- no generic card grid

## 5. Split Sticky Services

Use on Services page for premium layouts:
- left side sticky media
- right side service text blocks
- as user scrolls, media changes if data/assets allow
- if JS complexity is unnecessary, fallback to static media

## 6. Contact Trust Layout

Use on Appointment & Contact page:
- short about
- contact cards
- social links
- map/embed (or map fallback)
- opening hours
- CTA
- local trust copy

## 7. Footer Mega Layout

Desktop:
- 3 or 4 columns
- brand/summary
- pages
- services
- contact/social/map

Mobile:
- compact stacked sections
- no long unstructured list

## 8. Visual Rejection Rules

Reject if any of these are true:
- white equal cards are the main design pattern
- hero uses card-inside-card composition
- page is mostly text with little media
- crude placeholders are visible
- mobile header is overly tall
- footer is a plain list with weak hierarchy
